# 慢环：选币与军师团

代码在 `src/jiaoyi/slow/`。慢环只写作战卡，不碰下单（`jiaoyi.execution` 不许导入）。

## 开会频率和成本

TradingAgents 每个标的一次会议大约 16–22 次 LLM 调用，DeepSeek 思考模型还会偶尔把结构化输出
退回成自由文本（上游 issue #750 / #1390 / #82 / #1461）。所以默认值是：

| 项 | 默认 | 说明 |
|---|---|---|
| 同一个币两次会议的最小间隔 | 2 小时（`symbol_min_interval`，建议 2–4 小时） | 没有触发就沿用上一张卡里这个币的指令，不花钱 |
| 触发重开会 | 卡到期前、关键位被破、大新闻、新入池 | 关键位突破和大新闻会无视最小间隔，只给该币重开 |
| 卡片有效期 | 2 小时（1–4 小时） | |
| 并发 | 8（`concurrency`，原 4） | 最多同时开 8 个币的会；撞限流靠 `llm_max_retries`（6 次退避重试） |
| 整体防抖 | 5 分钟内不连续开会 | |

## 独立更新大盘与各币研究来源

`regime_flip_*` 检查沿用原门槛：默认每 5 分钟采样，有效币中至少 30/40（75%）同向，
BTC 相对市场参照同向走至少 1%，连续 2 次满足后调用独立市场模型。旧观点看涨只检测向下，
看跌只检测向上；中性对称检测上下，两边同时满足时不选边。缺数据、限流会清确认，
单币会忙不会跳过采样或清确认。市场更新已在途时合并重复请求，沿用原最少间隔和日预算。

独立市场任务只更新 `MarketView` 的判断、结构化方向、时间和版本，不调用各币 `analyze`，
不选币、不改池成员/分档、不更改已有币的方向、允许信号、有效期、卡版本或定期整轮时间。
市场分析前重新抓取原池成员的行情统计，仅用于本次评估，不发布新候选池，也不推迟选币。
沿用整轮会前 2 分钟统计新鲜度要求；统计缺失、过旧、超时或模型失败都保留上一份市场观点，
记真实费用并按原失败退避，不发布新时间冒充新观点。每次会议显式传入冻结的简报，
市场任务与单币会、整轮会的预算预留和实况状态分开；较旧结果不能覆盖较新的市场观点。

`data/market_view.json` 独立保存最新市场、参照、翻转间隔和市场失败退避，重启可恢复。
同方向刷新不滚动 BTC 参照；结构化观点方向真正改变时，方向、当时新鲜 BTC 价和时间一起推进，
以便继续检测下一次反转。缺少新鲜 BTC 时暂停该新状态的翻转检测，等有效价格再原子建参照；
定期整轮成功仍按市场阶段完成时的价格建立参照，较旧整轮不能覆盖新的市场状态。

各币 `source_market_view_id` / `source_regime` 记录研究启动时的来源，旧卡默认空并回退整卡判断。
`BattleCard.regime` / `regime_direction` 保留出卡时背景，旧卡没有结构化方向时不猜，`current()` 的只读 `current_market` 另带最新市场。
进场拍板、管家快照及后续单币补会使用最新背景，不会把旧币指令伪装成已重新研究。
Jev 等待或读账户期间市场方向变化会放弃这次旧背景答案，限价追单同样复核；
同方向的文字更新不额外拦单。快照结构标记为 q9/s6，决策题文本和概率阈值保持原样。
总览分别显示最新大盘及行情来源时间、出卡时大盘；哨兵日志记录检查和独立更新结果。

## 大盘更新后的相关卡与持仓复核

仍由原哨兵每 5 分钟检查行情、按原连续确认和翻转间隔触发独立总盘；正常定时整轮也保留。
这里没有新增每 10 分钟调用总盘模型。大盘标签即使仍为中性，有效更新中的事实仍可触发下面两条复核链。

总盘在原同一次模型调用中，可以返回可选的 `review_candidates`：只提名原池与现卡交集的币，
说明新行情数字如何挑战旧研究假设，并复制该币的 `research_token` 和具体数字证据。
指挥官逐项核对证据属于本次新鲜快照、币和研究令牌一致；“市场版本变新”或卡龄本身不是理由。
普通整轮已安排 `to_meet` 的币不会再排临时会；没有依据的币沿用现有指令，不全池重跑。
`fast_loop.market_review_on` 默认开，可热更新；还必须打开总临时会 `schedule.event_meeting_enabled`。
它不依赖用户旧 `event_triggers` 名单，不直接修改方向、允许信号或有效期。

合法提名进入原单币临时会队列，继续遵守持仓优先、同币间隔、日次数、日预算和失败退避。
同币合并保留首次排队和最早可执行时间，30 分钟处理窗口从可执行时刻算，避免 60 分钟冷却前先过期。
每种其他真实事件保留自己的首次排队时间，撤销市场原因不会抹掉新事件。
只有模型明确提供完整有效的候选集合（包括 `[]`），才撤销本次未再提名的旧市场原因；
字段省略或提名元数据不可用时记录 `reviews_valid=false`，保留排队位置但暂停市场原因，
等待新版完整集合重新确认；其他仍有效的真实事件照常，不影响大盘有效结果。
排队及实际开会前都核对本币研究令牌；无关币换卡不使它失效。
正在进行的单币研究冻结启动时的市场背景，多次市场更新不会取消重开；完成时仅合并该币结果。

每次被采纳的大盘发布也会唤醒原持仓管家通道，现有 30 秒左右巡检继续兜底。
同仓仍只允许一场 Jev 在途，全局并发上限不变，硬止损和执行不等待这些复核。
`KeeperVerdict` 从实际发送给 Jev 的快照记录 `source_market_view_id` / `source_market_version`；
只有成功完整回答才 `review_succeeded=true`。旧在途回复只能确认实际用过的旧版本，
不能清掉更新版本的待处理目标；失败按现有重试和巡检继续，仓位关闭则清理。
即使作战卡已过期或缺失，管家仍从独立只读回调取得最新市场背景，不合成开仓卡。
管家 ACTION 问法、概率阈值和交易权限都保持原样，不因市场更新全体平仓或停止开仓。

卡提名、排队、忽略/撤销、开始、完成/失败写入军师团中文日志；持仓待处理与实际源版本写入管家日志。
卡行单独显示研究时大盘，最新大盘仍独立展示，不冒充新卡。
队列保存在 `market_view.json`，持仓待处理/已处理进度保存在 `keeper_market.json`，重启可接续。
新增契约字段均有默认值，旧卡、旧管家结果和未提供提名的旧模型仍可读取。

## 会议输出不合格就是“这个币没有结论”

- 结构化输出解析失败（含退回成自由文本）→ 重试一次，仍失败则该币没有结论。
- 名义价值上限或杠杆上限超过 `config/risk.toml` 的硬上限 → 该币没有结论（不是悄悄夹紧后照用）。
- 分组与候选池不一致、返回了别的标的 → 该币没有结论。
- 所有币都没有结论 → 抛 `CardRefreshError`，不出新卡；旧卡到期后快环不再开新仓。
- 没有结论的币不在卡里，快环对不在卡里的币不开仓。

`stop_atr` / `take_profit_r` 在硬上限里没有对应项，这里不夹，风控员签发时必须自己再核一遍。

## 新闻与公告源（`slow/news.py`）

| 源 | 角色 | 说明 |
|---|---|---|
| 币安公告 | 主源 | 公开接口（非官方，改版会坏→解析失败直接报错，不猜），中文；上新 48、下架 161、动态 49、API 51 |
| 欧易公告 | 辅源 | 官方公开接口；注意出口 IP 不同看到的站点（全球 / 美国）不同，上线时在曼谷复查 |
| CoinDesk / Cointelegraph / The Block RSS | 背景 | 行业新闻，只喂给会议，**不触发开会**；用 defusedxml 解析 |

- 可插拔：实现 `NewsSource.fetch()` 即可加源。每个源独立失败；状态变化（挂 / 恢复）才写一条决策日志，全挂时会议照开，只是没有新闻。
- 同步读缓存：`NewsHub.for_symbol / market` 只读内存，TradingAgents 的工作线程直接调用，不碰网络。主循环定时调 `poll_and_notify`（建议公告 1–5 分钟、RSS 15 分钟；目前统一一个周期，按需拆）。
- 喂给会议：TradingAgents 的 `get_news` / `get_global_news` 路由到 `crypto_news`（加密币读 NewsHub，美股永续回退 yfinance）；总盘会的提示里带市场摘要和每个候选币的最近标题。
- 触发开会：公告类新条目提到候选币 → `BattleCardCommander.notify_news`。
- **币安下架公告 → 禁止新开仓**：7 天内的币安下架 / 移除公告提到我们交易的币 → `block_symbol`，作战卡里该币立刻读成“只看不做”（风控员本来就只认卡，所以不用改风控员；封币 = 不再开仓，已有持仓由持仓管家在约 40 秒后平掉并推 Telegram——要下架的币留仓更危险；这是持仓管家对「只看不做」唯一还会投平仓票的情况）。宁可多挡：现货交易对移除的公告提到同名币也会挡。进程重启后由新闻源重新补上。

接线（主循环，架构师）：创建 `NewsHub(default_sources(), log)`，传给 `TradingAgentsEngine(news=hub)`，并定时 `await hub.poll_and_notify(pool_symbols, commander.notify_news, commander.block_symbol)`。

## 误封后怎么解封

下架公告匹配是宽松的（宁可多挡，例如现货交易对移除公告提到同名币）。目前 `BattleCardCommander.unblock_symbol(symbol)` 只有代码入口；进程重启后会由新闻源按 7 天窗口重新补封。要给人一个入口，需要架构师在 `app.py` / 面板的“设置”页暴露 `blocked_symbols` 和 `unblock_symbol`（同时显示被封的币和原因）。在那之前，误封的处理办法是等公告超出 7 天，或在代码里调用 `unblock_symbol`。

## 强平数据

慢环**不另开强平连接**。快环行情层连一路全市场强平流（`!forceOrder@arr`）并滚动统计 1 小时名义额，慢环只依赖窄接口 `slow.liquidations.LiquidationSource.liquidations_1h_usdt(symbol, now)`，没有新契约。

- 选币：`BinanceStatsSource(liquidations=...)` 把它填进 `SymbolStats.liquidations_1h_usdt`，参与打分（占 10% 权重，约 1000 万 USDT 封顶）。
- 会议：`TradingAgentsEngine(liquidations=...)` 把近 1 小时强平写进 `get_stock_data` 的衍生品段和总盘会的候选表。
- 接线（架构师）：把快环的统计对象同时传给 `BinanceStatsSource` 和 `TradingAgentsEngine`；没传则强平为 0 / 不显示，不影响其它功能。
- 多空拆分（多头被强平 vs 空头被强平）等快环 PR 合并后再加，需要对齐它的 `stats()` 返回结构。

## 共享市场简报（`slow/brief.py`）

每轮开会前由 `BattleCardCommander` 调一次 `MarketBriefService.refresh()`，所有标的的会议共用，不再每个会议各查一遍大盘。内容：BTC / ETH 趋势（日线、4 小时线）、恐慌贪婪指数（alternative.me，免费无 key）。每部分独立失败，全失败则沿用上一份，简报挂了会议照开（记一条错误日志）。

- 进入会议：总盘会提示、单标的结论整理提示、都带这份简报。
- **美元指数（DXY）暂未接**：没有稳定的免费无 key 来源（试过的站点会拦截脚本请求）。要加就实现一个 `BriefPart` 加进 `default_parts()`。
- 接线（架构师）：创建一个 `MarketBriefService()`，同时传给 `BattleCardCommander(brief=...)` 和 `TradingAgentsEngine(brief=...)`，退出时 `aclose()`。

## 成本与节奏配置（`slow/settings.py`，可选 `config/slow.toml`）

开会花多少钱、多频繁，都能在 `config/slow.toml` 里调（示例见 `config/slow.example.toml`）：

- `[meeting]`：每类标的请哪几位分析师（`market/social/news/fundamentals`，至少一位、不重复）、多空辩论和风控讨论轮数（0–3）、flash/pro 模型名、挑币会议和“整理作战指令”两步各用 `quick`（flash，便宜）还是 `deep`（深度档模型，默认与 quick 同为 4.1）、`max_tokens`、重试次数。
- `[schedule]`：并发（1–32）、作战卡有效期（1–4 小时）、同一个币两次会议最小间隔（0.5–12 小时）。
- `[prices]`：每百万 token 美元价，只用于花费统计（占位值，M2 真机按官网核对）。

没有这个文件就用默认值，**与不配置时行为完全一致**。写错字段或超范围直接拒绝启动（`ConfigError`）。这里**不放任何风控数值**，硬上限仍只在 `risk.toml`。

接线（架构师）：`cfg = load_slow_config()`，`TradingAgentsEngine(settings=cfg.engine_settings(), ...)`，`BattleCardCommander(..., **cfg.commander_kwargs())`。

## 作战卡复盘（`slow/review.py`）

出卡时 `BattleCardCommander(journal=CardJournal(data_dir))` 把**这次真开了会**的每个标的追加到 `data/card_review/cards.jsonl`（沿用旧卡的不重复记）。卡过期后：

```
python -m jiaoyi.slow.review --days 7        # 按方向 / 类别 / 出卡原因汇总
python -m jiaoyi.slow.review --json          # 逐条明细
```

用公开 5 分钟 K 线，在卡的有效期内算收盘涨跌、最大有利 / 不利波动；long/short 才算命中（方向收益 > 0），both / no_trade 只看波动。**只读报告，不会自动改任何权重、阈值或提示词。**样本少（几十条以内）时别当结论。接线（架构师）：创建 commander 时传 `journal=CardJournal(data_dir)`。

## 大模型来源：DeepSeek 直连或 OpenRouter

`config/slow.toml` 的 `[llm] provider` 选来源，默认 `deepseek`（直连，`DEEPSEEK_API_KEY`），行为不变。改成 `openrouter` 后走 TradingAgents 自带的 OpenRouter provider（`OPENROUTER_API_KEY`，`jiaoyi setup-keys OPENROUTER_API_KEY` 录入），仍是同一批 DeepSeek 模型：

| provider | quick（flash） | deep（pro） |
|---|---|---|
| deepseek | `deepseek-flash`（V4.1 Flash） | `deepseek-flash`（同上） |
| openrouter | `deepseek/deepseek-v4.1-flash-1017` | `deepseek/deepseek-v4.1-flash-1017` |

Aaron 决定深度档也用 4.1、不用 v4-pro，所以两档默认同一个模型；想换回 pro 在 `[meeting] deep_model` 写 `deepseek-v4-pro`（OpenRouter 为 `deepseek/deepseek-v4-pro`）。OpenRouter 的 id 核对于 2026-10-23（`/api/v1/models`），`[meeting] quick_model / deep_model` 写了就覆盖默认。结构化输出的重试逻辑、成本统计（按模型名里有没有 `pro` 分档）不变；OpenRouter 的实际单价随上游供应商浮动，`[prices]` 仍是占位，M2 真机后按账单核对。没有对应 key 时军师团退回桩（不出卡、不开新仓）。

## 失败退避与日花费上限

- **失败退避**：开会整轮失败（例如 DeepSeek 结构化输出持续出错）后，依次等 5 → 10 → 30 分钟再试，之后保持 30 分钟，成功一次清零（`[budget] fail_backoff_minutes`）。闸门在 `BattleCardCommander.may_refresh`，主循环的所有触发原因（含定时兜底）都要过它，不会每分钟重开最多 20 个币的会。
- **日花费上限**：`[budget] daily_cost_limit_usd`（默认 10 美元，0 = 不限：不停开会、也不放慢，花费照常统计，花过本档默认日上限（15m 75 / 30m 40 / 1h 30 / 2h 20 / 6h 10 / 12h、24h 5）时每天推一条只提醒不停的消息；按 `day_reset_tz` 的交易日即曼谷 0 点清零）。超了当天不再开会，沿用现有作战卡（到期后不开新仓），并通过 Telegram 推一条提醒（每天一次）。
- 统计口径：只算成功记录下来的花费（总盘会 + 出了结论的标的）。整轮失败的会议没有可记的 token 用量，所以不进统计，靠上面的退避把这部分兜住。

## 每轮最多出几张作战卡

`[schedule] max_cards_per_round`（0–50，默认不写；0 = 不限，只受 `card_pick_max` 管）限制每轮开会的标的数，也就是一张作战卡里最多有几个标的。不写就用 `app.toml` 的 `card_pick_max`（行为不变）；写了取两者较小值，所以不会超过 `card_pick_max`。顺序：置顶币先占名额，剩下的名额由总盘会按选币评分和行情挑，超出名额的不开会。想省钱先降这个数，开会次数和花费大致成正比。当前上限会显示在军师团的状态要点里（面板“团队”页）。

### 日花费统计的口径（补）

日花费上限的统计包含失败的花费：会议失败时按引擎带出的真实 token 用量计（`MeetingError.cost_usd`）；超时、断网等拿不到用量时，按 `[budget] failed_meeting_cost_usd`（默认 0.05 美元）估算计。总盘会（选币）一出结果就计入，哪怕之后所有标的都失败；会议给出的结论被代码判为不合格（别的标的、越界）时，它的花费也照计。当天已花的钱落在 `data/slow_budget.json`（按曼谷交易日），重启后读回，跨天自动清零；文件读写失败只影响重启恢复，不影响出卡。
## 止损 ATR 的周期（跟风控配置走）

作战卡里的 `stop_atr` 是 **ATR(14) 的倍数，周期由 `risk.toml` 的 `atr_period_min` 决定**（5/15/30/60 分钟，默认 15；Wilder 平滑，与快环特征层、风控员同一算法）。整理作战指令的提示词里不写死周期：它按配置写明周期，附上该币当前这个周期的 ATR 数值和占价格的百分比（取不到时明说“暂不可用”），并告诉军师止损倍数必须落在 `fast_loop.min_stop_atr`–`max_stop_atr` 之间。会议分析师看到的指标仍是 1h K 线，那是看趋势用的，不是止损尺度。

慢环这边也把 `stop_atr` 夹进 `[min_stop_atr, max_stop_atr]`、`take_profit_r` 夹进 `[min_tp_r, max_tp_r]`（`clamp_to_risk`，都来自 `fast_loop`），提示词里同样写明这两个区间。军师给出 0.2–0.4 倍这类过近的止损、或低于下限的止盈倍数，会被抬到下限，而不是让风控员把整张卡的这个标的拒掉白开会。

## 安装与启动检查

`make install` 默认连军师团依赖（`.[dev,slow]`，TradingAgents 钉提交）一起装。配了军师团的 key（`DEEPSEEK_API_KEY` 或 `OPENROUTER_API_KEY`，看 `[llm] provider`）却没装 `tradingagents` 时，`jiaoyi run / status` 和 `jiaoyi check-config` 直接报错退出，**不再静默用桩**——否则 M2 会空跑（不出卡、不开新仓却看不出来）。没有 key 时仍用桩，M0/M1 照常。

## M2 实跑后的三处小修

- **欧易公告**：原来的 `announcements-trading-rules` 类型已下线（返回 400），换成 `new-listings / delistings / api`；某一类型失败不影响其余，只有全部失败才算该来源失败。同一来源的报错记录最多每 30 分钟一条。
- **Reddit 限流**：匿名 RSS 约每分钟一次，多标的并发开会必然 429。`[social] reddit = "guarded"`（默认）给抓取加闸：同币 30 分钟缓存、两次真实请求至少隔 65 秒（其间不等待，返回“不可用”占位）、失败后冷却 10 分钟；`"off"` 则完全不抓。占位文字写明“不可用不等于没人讨论”，Reddit 只是情绪的背景数据之一。
- **结构化输出回退**：DeepSeek 偶尔让 Research Manager / Trader 的结构化输出失败（约每轮一次），TradingAgents 会改用自由文本再调一次。这一次调用同样挂在带计费回调的 LLM 客户端上，所以费用照常计入当日预算；回退得到的是自由文本，由后面的作战卡转换步骤统一解析，解析不了则该标的本轮不出卡。

## 指标补全与作战卡即时落盘

- **技术指标**：币安数据源（小时线）现在支持 TradingAgents 技术面分析师会要的全部指标：`close_N_sma / close_N_ema / rsi / atr / macd / macds / macdh / boll / boll_ub / boll_lb / vwma / mfi`（布林 20 根 ±2σ，VWMA 20 根，MFI 14 根）。分析师若点了不认识的名字，返回“不支持，可用：…”的文字让它换一个，不再让整场会议失败。
- **每场会议结束立即出卡**：一个标的开完会就把它并进当前卡、版本号 +1、写到 `data/battle_card.json`（连同各币上次开会时间）。重启后没过期的卡直接捡回来，也不会为刚开过会的币重复开。还没轮到的币在本轮结束前不在卡上（保守：没有指令就不开新仓）。

### 开会期间的卡与持仓币（审计 I8）

- 一轮里还没轮到（或开会失败）的币，**沿用上一张卡的指令**，开完哪个换哪个；上一张卡已过期就不沿用旧指令。没有新结论的失败币在本轮结束时从卡上拿掉。
- 有持仓的币必须一直在卡上：本轮没入选或开会失败的，清空信号、方向不动（改成 NO_TRADE 会被持仓管家当平仓理由）（持仓管家只会继续盯，不会因“不再盯”平仓）。循环在每次开会前用 `set_held` 告诉军师团当前持仓。
- 重启恢复的卡：按当前 `risk.toml` / 止损档位再夹一遍；出卡时的 ATR 周期和止损倍数区间与现在不一致就不恢复，等下一轮会。

- **开会期间的心跳**：一轮会议要十几分钟，期间每开完一场、以及每 30 秒都上报一次心跳，详情写“开会中：3/8”，面板不会把慢环标红。
- **封币与持仓**：封币 = 不再开仓，已有持仓由持仓管家约 40 秒后平掉并推 Telegram（要下架的币留仓更危险）。
- **持仓币强制入选（R5b）**：有持仓的币（候选池内的）每轮强制开会，和置顶一样不占军师的挑选名额。没有新结论时沿用旧指令（清空信号）；旧卡里也没有它（切档重启丢了旧卡、卡文件没了、币已不在池里）就按持仓方向合成一条“只盯不开”，所以持仓币永远不会从卡上消失。
## 关键位由代码算，军师只能选（M2 现场反馈）

第一张卡里 BTC 的关键位（现价 ~81600 报 86000 / 72859.5）是模型凭印象编的：不分支撑压力、没排序、离现价很远。现在：

- **候选由代码算**（`slow/levels.py`）：昨日 / 7 日高低点、近 7 天 1h 的摆动高低点、成交密集区、整数关口；只留现价 ±4×ATR（取“止损周期 ATR”和“1h ATR”里大的）以内的，相近的合并，按距现价从近到远。
- **提示词里列出候选**（支撑 / 压力两组，各最多 5 个），要求 `key_levels` 只能从候选里选。
- **落到卡上前再对回候选**：军师给的价位在 0.5×ATR 内就换成最近的候选（类型以现价上下为准，不信模型报的类型），对不上的丢掉；每边最多 3 个，先支撑后压力、各自从近到远。行情拿不到就不出关键位，不瞎编。
- **永续合约语境**：TradingAgents 的提示词是写死的股票语境（Buy / Overweight / Underweight、“减持”）。它会把 `output_language` 原样拼进每个角色的提示词，所以我们在这个字符串里加了永续合约的说明（多 / 空 / 观望，Underweight = 偏空或观望，不要“减持”），并在转换作战指令的提示词里明确 Buy/Overweight→偏多、Sell→偏空、Underweight→偏空或观望、Hold→观望。评级行本身仍是英文（TradingAgents 程序读它）。

- **落盘与心跳**：作战卡每场会后写 `<data_dir>/battle_card.json`（启动日志会打印它的绝对路径；写失败会记 ERROR 日志，不再静默）。军师团的心跳由应用每 30 秒统一上报：空闲时写“当前卡 vN，M 个可做，下次会议 HH:MM”，重启恢复后写“已恢复卡 vN…”，失败退避中写重试时间，会议中写“开会中：k/N”。

- **会议花费预记（X2）**：每场会议（含总盘会）开始前先按估算（最近几场实际花费的均值，没有就用 `failed_meeting_cost_usd`）记进当日预算并立即落盘，结束后改成实际值。被强退（重启）打断的会议不会漏记，每次重启最多多记一笔估算。


## 选币页的固定 / 拉黑 / 手动加入

存在 `data/pool_overrides.json`（`core/pool_overrides.py`），AI 改不了。面板发指令（`pin_symbol`、`unpin_symbol`、`blacklist_symbol`、`unblacklist_symbol`、`add_symbol`、`remove_symbol`，参数 `symbol`），主循环执行：改文件 → 立即重新选币。拉黑的币立即不开新仓（不等军师团下一轮出卡），也不再进池；固定和手动加入的币仍要过硬门槛，不占类别名额。手改文件也行，下一次选币（每小时）读到；文件读不出时运行中沿用上一份，启动时发 CRITICAL 告警并暂停开新仓（拉黑清单没生效，已有持仓照常看管），修好或删掉后重启自动恢复。

选币其余参数：池子大小 `app.toml` 的 `pool_size`、每轮挑几个 `card_pick_max`（面板设置页可改）；硬门槛（成交额 2000 万 U、深度 10 万 U、上线 7 天）、打分权重、每类上限 30、每小时选一次目前是代码默认（`slow/screener.py` 的 `ScreenerConfig`），点差门槛跟 `risk.toml` 的 `max_spread_bps` 走。

### 关键位范围按持仓时长统一缩放（Aaron：BTC / ETH 根本波动不了这么大）

关键位只给“持仓期内碰得到”的：范围 = `levels.span_sigma`（默认 1.5）× **该币自己的 ATR**（档位对应的周期：5 / 15 / 30 / 60 分钟）× √(持仓时长 / ATR 周期)。ATR 乘根号时间就是持仓期内价格的典型波动，所以**同一条公式适用所有币、所有档位**——波动大的币范围自动宽、BTC / ETH 自动窄，没有按币种的特例，也没有百分比表。例：ETH 现价 2390、15m ATR ≈ 6，2h 档范围 ≈ ±25（约 1%），不再出现 −9.8% 的支撑。摆动点和成交密集区也改用档位周期的 K 线（不再用 1h）。

提示词里同时告诉军师团持仓时长和该币持仓期内的一个标准差波动（TradingAgents 各角色的提示词里也带上“每笔最多持有约 N 分钟，目标价 / 止损 / 关键位按这个时长内该币的波动来给”），止损 / 止盈建议跟着收紧。持仓时长取自单笔最长持仓（`fast_loop.time_limit_s`，独立于档位）。

## 并发上限 8 → 32（`concurrency`）

`[schedule] concurrency` 上限从 8 提到 32，默认仍 8（各档位一致）。整轮各币会和临时会合计不超过它。调到 16 时要知道的：

- **线程**：单币会议跑在引擎自己的线程池里（最多 64 个线程，用到才建：会议最多 32 场同时开，超时取消的会议线程要等它在途的那个请求结束才退出，期间仍占线程，留到 2 倍不挤掉新开的会），不再用 `asyncio.to_thread` 的默认池——默认池只有 min(32, CPU 数 + 4) 个线程（10 核 Mac mini 上 14 个），并发 16 时多出来的会议会在池里干等、照样计 `symbol_timeout_s`，还会占满主程序别处的 `to_thread`（大盘台材料、简报取价、额度检查）。总盘会、独立大盘更新仍用默认池（同时只有一场）。
- **币安 REST 权重**：每场单币会开始时拉 K 线表、ATR / 止损用的 K 线、资金费率、持仓量历史、标记价，粗估每场 20–35 权重（K 线 500 根一次 5、300 根一次 2）。16 场几乎同时开 ≈ 300–560 权重，集中在开会头一两分钟；IP 上限 2400 / 分钟。所有会议线程共用 `binance_gate`：请求之间至少隔 50 毫秒（全局最多约 20 次 / 秒），本分钟已用权重过半就等到下一分钟，收到 418 / 429 全体停发，所以并发调高只会让开头的数据请求排得更长，不会把 IP 打封；但快环同一个 IP 也在用权重，开头那一分钟里快环可能被「过半就等」拖慢。
- **OpenRouter**：每场会议开头几位分析师（默认 market / social / news 三位，外加记忆整理）同时问模型，之后辩论 → 交易员 → 风控 → 组合经理一步一步问。并发 16 场同时开头时最多约 16 × 3 = 48 个请求同时在飞（8 并发时约 24），之后回落到约 16 个；请求速率约是 8 并发时的两倍。撞 429 靠 `llm_max_retries`（默认 6 次退避重试）；重试多了单场耗时变长，可能碰到 `symbol_timeout_s`。日花费按次数涨，`daily_cost_limit_usd` 照常管着。
- **整轮耗时估算**（`caution()` 的「最坏一轮 = 波数 × 单币超时」）按 `ceil(每轮开会币数 / concurrency)` 算，自动跟着新的上限走，不用改。

## 单币会议超时

`[schedule] symbol_timeout_s` 默认 900 秒（原 600）。实测 30m 档一轮 4 并发会议时，SOL、XRP 在 600 秒被取消；耗时取决于并发数和分析师数，与档位无关，所以各档共用同一个值，不按档位拆。超时告警现在写明「超过 N 秒未完成（TimeoutError）」，不再是空原因。更根本的办法是降低并发（`concurrency`）或减少分析师，单币耗时随之稳定；本次不实现。

单币超时与换卡提前量要配套（验收 A4：一轮 p95 ≤ 提前量 − 5 分钟）：个别币拖到 `symbol_timeout_s` 才结束，旧卡过期后到新卡出来之间就不开新仓。所以 60m / 30m / 15m 档的 `refresh_lead_min` 默认从 15 提到 20，2h 档本来就是 20，都满足「超时秒数 ÷ 60 + 5 ≤ 提前量」。自己改配置时若不满足，`jiaoyi check-config` / `status` 和面板设置页的「军师团节奏」只显示提示，不拒绝。

## 费用按通道报的真实值计；并发、回答长度

- **费用**：走 OpenRouter 时每次请求带 `usage: {include: true}`，用响应里的 `usage.cost`（美元）累加，不再本地估算（`CostMeter`）。某次请求没报（直连 DeepSeek、通道没带字段）才按 `[prices]` 估这一次，flash 默认 0.30 / 1.20（OpenRouter deepseek-v4.1-flash 标价，2026-10-23）。Jev（快环）本来就是 `usage.cost` 优先、token 单价兜底，路径一致。
- **超时取消的会议**：指挥官在 `symbol_timeout_s` 到点时叫停引擎（该会议后台线程不再发新的模型请求），并按它已经发生的真实花费记账；只有断网这类拿不到任何用量的失败才记 `failed_meeting_cost_usd`。已发出的那一个请求照常结束，所以会略低估。
- **今日调用次数不随重启清零**：快环各角色重启时从决策日志读回今天的次数和花费；军师团的统计随 `data/slow_budget.json` 一起落盘恢复。
- **会议并发 4 → 8**（各档位一致），撞 OpenRouter 限流靠 `llm_max_retries`（6 次退避重试），没有改会议流程。**回答长度上限 8192 → 4096**，出作战指令和挑币两步（要输出 JSON）单独按 8192 起（`json_max_tokens`），不会被截断。

### 类别开关和每类上限

六个类别：`major` 主流币、`alt` 山寨币、`crypto_stock` 加密概念股、`us_tech` 美股科技、`precious_metal` 贵金属、`other`。每类可以关掉（不再靠打分进池）、可以设最多进池几个（0 = 一个都不要）。设置有两处，选币页优先：

- `slow.toml` 的 `[screener.categories.<类别>]`：`enabled`（默认 true）、`cap`（不写 = `default_category_cap`）。
- 选币页指令（写进 `data/pool_overrides.json` 的 `category_enabled` / `category_caps`，改完立即重新选币，要面板密码）：`set_category`（`params.category` + `params.enabled` = `true` / `false` / `default`）、`set_category_cap`（`params.category` + `params.cap` = 0–100 的整数或 `default`）。`default` = 清掉选币页这一项，回到 slow.toml。

规则：固定和手动加入的币比类别开关更具体，类别关了仍进池（也不占名额、不受上限限制，同以前），但仍要过硬门槛；拉黑最优先。被关掉的类别里没进池的币，选币页理由栏显示「这一类已关闭」。全部类别都关了会在 `check-config` 提示（候选池只剩固定 / 手动加入的币）。

## 选币状态

选币器自己上报 `module_status.json` 的 `screener`：`last_run_at`、`next_run_at`、`symbol_count`、`error`（`ModuleStatus` 新增的可选字段），headline 写明「等待首次选币 / 上次 HH:MM 选出 N 个币，下次 HH:MM / 上次选币失败，沿用旧候选池：原因」。面板和 `jiaoyi status` 不再出现「未接入或还没启动」：没上报过时，主程序在跑显示「等待第一次上报」，不在跑显示「主程序没在运行」；离线 / 回放模式的桩显示「未启用」。

## 开会过程实况（`data/meeting_live/<SYMBOL>.json`）

每个标的一个文件，开会时每走一步整份重写（同目录唯一名字的临时文件 + rename，面板读到的永远是完整 JSON）；一场会由多个线程写（并行的分析师各自线程里的模型回调、跑图线程、超时叫停的事件循环线程），每份实况一把锁、每个文件一把锁，写盘串行，最后一次写的就是最新状态。同一个币同时有两场会时（上一场超时取消、后台线程还没结束，下一场已经开了），文件归**最近开始的那场**：较早那场之后的发言和结论都不再写进文件，叫停（`abort`）也只作用于最近那场。会开完就不再占着文件。文件权限 0644。启动清理时顺带删掉上个进程死在写盘中途留下的临时文件（`.<SYMBOL>.json.*.tmp`，以及旧版本的 `<SYMBOL>.json.tmp`），本进程正在开的会的文件和临时文件不碰。会开完文件保留，就是这个币上一场会的完整过程，下一场开会时覆盖。**只旁听，不改决策、不多一次模型调用**：引擎把 TradingAgents 图的 `invoke` 换成同一张图的 `stream`（`stream_mode=["values","tasks"]` + 子图，与 TradingAgents 自带的 `stream_run` 相同，最终状态与 `invoke` 一致），每个新出现的发言记一步。写盘失败只记日志，不影响会议；开了 checkpoint（默认关）时图被重编译，实况会静默缺失，会议本身不受影响。

| 字段 | 说明 |
|---|---|
| `symbol`、`meeting_id` | 币和这场会的编号（`SYMBOL-时间`） |
| `status` | `running` 开会中 / `done` 有结论 / `failed` 失败（含超时取消，`error` 写原因） / `interrupted` 中断（`error` = 「主程序重启，会议中断」） |
| `process` | 写这份实况的进程标识。启动时把上个进程留下的、还标着 `running` 的实况（含没有此字段的旧文件）标成 `interrupted` 并写 `finished_at`；退出收尾（`Runner.shutdown`）也把本进程在开的会标成中断，之后工作线程再写会被忽略。重启中断不算开会失败：`_last_meeting` 只在开完时更新、失败退避（`_event_fail_until`）只在内存里、对取消不记失败，新进程第一轮就能重开这些币。会议线程池取消不掉，退出靠 `os._exit` 兜底，不会被它们拖住；「后台任务取消后 10 秒还没停」说的是 asyncio 任务（吞掉取消的任务），不是会议线程，不影响重启。 |
| `started_at`、`updated_at`、`finished_at` | ISO 时间（带时区），`finished_at` 开会中为 null |
| `stage` | 现在开到哪：`analysts` 分析师报告 → `debate` 多空辩论 + 研究经理 → `trader` 交易员计划 → `risk` 风控辩论 + 组合经理 → `decision` 整理成作战指令 |
| `steps[]` | 按发生顺序追加：`{stage, who, ts, text}`。`who`：`market` / `social` / `news` / `fundamentals`（分析师报告，并行跑，几乎同时到）、`bull` / `bear`（每轮新增的发言）、`research_manager`、`trader`、`aggressive` / `conservative` / `neutral`、`risk_manager`（最终决定原文）、`convert`（整理出的作战指令理由）。`text` 是原文 |
| `result` | `{bias, reason}`，`done` 才有，否则 null |
| `error` | 失败原因，否则 null |
| `cost_usd` | 这场会的花费（会议结束 / 失败时写入，开会中为 0） |

超时取消的会议会被指挥官叫停并立刻标成 `failed`（`超时取消，会议没有结论`）；后台线程之后才结束，不会把它改回成功。

## 回答长度：别低于 8192；空辩论按失败处理

Mac 实测（#96 把 `max_tokens` 降到 4096 后）：思考模型的思考也算在 `max_tokens` 里，个别币的多空辩论回答被思考挤成空的，历史里只剩「Bull Analyst:」空壳，研究经理看着空记录照样给 Hold，日志里还有「structured-output invocation failed」。所以默认改回 8192（`json_max_tokens` 仍是 8192 起）。另外加了一道检查：该开口的多头 / 空头 / 激进 / 保守 / 中立派只要有一位的发言是空的，这场会按失败处理（不给结论、不出卡、记花费），而不是拿空辩论出一张 Hold。

分析师并行核实：固定版本的图里 4 个分析师是并行的子图，实况里它们的时间戳不同是因为各自完成时间不同（情绪分析师没有工具调用最快，行情要多轮取数最慢），按完成先后写入——若是串行，顺序会是配置里的 market → social → news，而不是实测的 social → news → market。

实况文件另有 `llm_calls[]`（每次模型调用的 `finish_reason`、`output_tokens`，最多留最近 80 条）和 `truncated`（`finish_reason == "length"` 的次数），用来核对回答有没有被 `max_tokens` 截断。有任一次被截断，这场会按失败处理（`error` 写明），沿用旧指令。

后续选项（本次不做）：OpenRouter 支持限制推理长度（请求里的 `reasoning` 参数，如 `effort` 或 `max_tokens`），可以让思考不再挤占正文额度；会影响分析质量，要单独验证再开。

## 选币器的门槛和权重（`[screener]`）

选币每小时用代码跑一遍（不用 AI）：先过硬门槛，再按权重打分，取前 N 个（`pool_size`，在 app.toml）进候选池；你在选币页固定 / 拉黑 / 手动加的币优先于打分。以前写死在代码里的参数现在都在 `config/slow.toml` 的 `[screener]`，不写就是原来的值（选币结果不变）。你定的值就是上限，只提示不拦；只有数学上不成立（五项权重全 0、波动下限 ≥ 上限）才拒绝启动，`jiaoyi check-config` 会校验并打印提示。

### 执行所上做不了的币（`exclude_untradeable`，默认 `true`）

选币用主网数据，下单在执行所（Demo / 实盘）。`exclude_untradeable = true` 时，执行所上状态不是 TRADING（如 `PUMPUSDT` 结算中 `SETTLING`）**或没有下单精度**（exchangeInfo 里没有这个合约的 lot 规则，`无下单精度`）的币当成没过硬门槛：不进池、不上会、不占卡位，名额给下一个币；固定 / 手动加入的币也一样。原因写在选币页（`Demo不可交易（无下单精度）`），候选池文件记 `venue_excluded`，作战卡上已有的这类币读成只看不做（持仓币不动）。面板设置页能改，也能写进 `config/slow.pending.toml`。

为什么默认开：`PUMPUSDT` 曾在卡上 61 小时（能交易的 22.8 小时），出了 18 个信号，Jev 问了 18 次，全部被风控员以「没有这个合约的交易所精度」拒掉，按主网模拟是 −0.39R。

拉不到下单精度时**不按精度剔币**（失败安全，不会把池子清空）：执行所下单精度从没拉到或已过期（`lot_rules` 缓存超过有效期）时，这一轮整份名单都不用；拉到了，但判断的币里超过一半（`VENUE_MAX_EXCLUDED_FRAC = 0.5`）是「无下单精度」（像是 exchangeInfo 没拉全，不像真下架），只丢掉「无下单精度」这部分，按交易所状态（SETTLING 等，同一次拉取读到的）的照剔。两种情况都记一条 WARNING（「Demo下单精度没拉到或已过期 …」/「Demo下单精度里没有 N / M 个币，像是没拉全 … 只按交易所状态剔币」）。选币器和「作战卡上已有的币读成只看不做」走同一个判断（`screener.trusted_venue_off`）：选币按过了其余硬门槛的币算比例，作战卡按卡上的币加当前池子里的币算。这种时候风控员照旧对没有精度的币拒单。

回滚：`[screener] exclude_untradeable = false`（面板「选币」里能改），选币不再管执行所状态，回到 #355 之前。

## 推理长度（`[meeting] reasoning_effort`，默认 `low`）

Mac 实测（#98 把 `max_tokens` 改回 8192 后）：deepseek-v4.1-flash 是推理模型，推理 token 也算在输出额度里，个别币（ADA / BTC / TIA）的辩论回答只有几千字却用满 8192，`finish_reason=length`，整场失败；加长度治标不治本。所以走 OpenRouter 时，所有会议对话步都带 `reasoning` 参数限制推理：`low`（默认）/ `medium` / `high` 对应 OpenRouter 的 `reasoning.effort`，`none` 对应 `reasoning.enabled=false`（关掉推理）。参数直接设到 TradingAgents 建好的模型对象的 `extra_body`（`apply_openrouter_options`，请求体里还有 `usage.include` 取真实花费），单元测试验证了请求体。直连 DeepSeek（`provider = "deepseek"`）这个参数不生效。推理变短可能略降分析深度；觉得质量不够再调成 `medium`，截断仍然会让整场失败（#98 的兜底）。

### 分档交易（`[screener.tiers]`）

设计文档 §六：「头部档先开放，中间档由军师每天挑，尾部只看不做」。设计稿没有写具体数字和仓位系数，下面是按**最保守**的理解做的假设（都可以在 `[screener.tiers]` 改，`enabled = false` 回到不分档、整个池都开会）：

| 档 | 怎么分 | 怎么交易 |
| --- | --- | --- |
| 头部 head | 你固定 / 手动加入的币，加上池里分数最高的，凑满 `head`（默认 10）个 | 每轮都开会，和以前完全一样 |
| 中间 mid | 头部之后的 `mid`（默认 15）个 | 每天（曼谷日）第一轮由总盘会从中间档里挑，最多 `mid_daily_pick`（默认 5）个，当天才继续开会；其余当天不开。挑中的币卡上的仓位档位最大封到 `mid_size_max`（默认 S，只往小夹） |
| 尾部 tail | 其余的 | 留在池里让快环录数据，**不开会、卡上没有、不开新仓** |

- 有持仓的币不论哪一档都照常开会、留在卡上（不然持仓管家看不到它）。
- 档位写在候选池每个币的 `tier` 字段（面板选币页可显示）。
- 当天的中间档挑选结果存 `data/mid_tier.json`，重启不重挑；换日后的第一轮会议重新挑。
- 分档靠池里的分数排序，所以打分 / 类别开关 / 池子大小的设置都会影响谁在头部。
- `always_candidates`（默认 BTC、ETH）：每轮都进候选池，但挑不挑仍由总盘会决定。`always_candidates_meet = true`（默认 false）时，这些币每轮整轮会都**不经挑选**直接开单币会议（会议自己定做多 / 做空 / 不做），不占 `max_cards_per_round` / `card_pick_max` 的挑币名额，军师照样挑满原来的个数；分档关了也一样。仍受这些限制：要过硬门槛和拉黑（不在池里就不开）、执行交易所上不在交易的币不开（交给总盘会照常挑）、同币最小间隔内没有大消息沿用上一张卡、会议并发、日花费上限、类别敞口；临时会不受影响。总盘会实况的 `filter` 一步、`data/market_meeting/` 记录里的 `direct_meet` 和这些币的 `reason` 写「每轮直接开会（设置）」。这些币在记录的 `pool` 行里是 `pick = true`，但不是 Flash 挑的：离线统计总盘会挑得准不准时，要先剔掉当轮 `direct_meet` 里的币。每轮场数 = 挑的个数 + 直接开会的个数，超过 `concurrency` 时设置页和 `check-config` 会提示；军师团心跳写「每轮最多 N 张 + M 个直接开会」。改了要重启。

### 美股开盘和财报（`us_events` / `us_open_bonus`）

只对 `crypto_stock`、`us_tech` 两类：
- **开盘加分**：美东常规盘（9:30–16:00，周一到周五，NYSE 全天休市日除外）期间总分加 `us_open_bonus`（默认 0.08），理由栏显示「美股开盘中」，分项里多一项 `us_open`。提前收盘的半天交易日按全天算。
- **财报标注**：用 Nasdaq 免费财报日历（无需 key，缓存 6 小时，拉昨天到 3 天后），财报日前后（昨天到 3 天后）在选币理由里标「财报：10-27 盘后（明天）」，**只标注不改分**；同时作为背景新闻进军师团的新闻（不触发开会）。拉不到就沿用旧缓存，只记日志，不影响选币和开会。
- 休市时不加分；`us_events = false` 整个关掉。

### 总盘会实况（`meeting_live/_MARKET.json`）

总盘会（大盘基调 + 挑币）和单币会议一样落盘，固定名字 `_MARKET`，字段同单币格式（status / cost_usd / steps…）。steps 依次是：`input`（候选池摘要：每个币的类别、分数、档位、理由，以及固定 / 持仓强制开会几个、还剩几个名额）、`pick`（大盘判断 + 挑中的币和一句理由）、`filter`（没进会议的币和原因：固定 / 持仓强制开会、军师没挑、超出名额、N 分钟前开过会沿用旧指令）。失败时 status = failed，error 里是原因。面板的会议页读得到它。

## 回答出问题自动重试、max_tokens 默认取模型最大

Mac 实测（#103 把推理限制成 `low` 后）：`length` 次数从每轮 8 次降到 3 次，但个别币（LINK / SOL）仍有几步被截断或回答为空，整场失败。现在：

- **自动重试一次**（`[meeting] retry_bad_steps`，默认开）：任何一步模型回答 `finish_reason=length`、正文为空、或少于 `retry_min_chars`（默认 20）字（带工具调用的回答不算），自动再问一次：提示里追加「直接给结论，不要思考过程。」，走 OpenRouter 时请求同时带 `reasoning: {"enabled": false}`（关掉推理）。重试拿到好回答就继续，那次截断不再让整场失败；重试仍不行才照旧整场失败（#98 的检查）。实况里 `retries` / `retry_reasons` 记重试次数和原因。
- **`llm_calls` 多记 `reasoning_tokens`**：每次调用其中推理用了多少 token（来自 OpenRouter 的 `completion_tokens_details.reasoning_tokens`），看推理是不是在吃输出额度。
- **`max_tokens` 默认取模型最大输出**（slow.toml `[meeting] max_tokens` 不写）：引擎启动时从 `https://openrouter.ai/api/v1/models` 读该模型的 `top_provider.max_completion_tokens`（deepseek-v4.1-flash 约 94 万；quick / deep 两个模型取小）；读不到、没有这个模型时 OpenRouter 用 384000，直连 DeepSeek 用 8192。写了数值就按你写的（出作战指令 / 挑币两步仍至少 8192）。注意：不设上限后，推理失控时一次回答最多能烧到这个长度——`reasoning_effort` 和重试关推理就是用来兜这个的，花费另有日上限。
- `reasoning_effort` 默认值先不动（仍 `low`），等重试的数据再定是否改 `none`。

## 会议质量门槛

一场会开完、转成作战指令之前（以及转完之后）按下面几条检查；不合格的会**整场失败**：没有持仓的币不留旧指令（卡上去掉），有持仓的币改成只看不做继续盯（同以前的失败处理）。门槛都在 `[meeting]` 里可调，只对失败的这一场生效，不影响其它币。

1. **分析师报告**（`report_min_chars`，默认 50）：请来的每位分析师的报告，为空、少于该字数、或短于 300 字且含工具报错字样（Traceback、rate limit、无法获取……）算缺失。**行情技术**缺失 → 整场失败；**新闻 / 社交 / 基本面**缺失 → 照常出结论，但卡上该币的仓位档位下调一级（L→M→S），理由里注明「X 报告缺失，仓位档位下调一级」，实况多一步 `quality`。
2. **每个辩手每轮发言**（`speech_min_chars`，默认 50 字；0 = 只查空）：多空、三位风控每人每轮至少这么多字（多轮时历史各轮拼接，按「轮数 × 字数」查）。不够 → 整场失败，提示是哪几位。
3. **方向一致**：转出来的作战指令是做多 / 做空时，会议自己的结论不能相反——组合经理评级是 Sell / Underweight 却要做多，或 Buy / Overweight 却要做空，交易员的 `FINAL TRANSACTION PROPOSAL` 是 SELL 却要做多、BUY 却要做空，都整场失败（观望 / 持有 / 解析不出来不算矛盾；NO_TRADE 不检查）。

代码对「请不请某位分析师」不做判断，只查请来了的。决定按这套门槛放行的会，行为同以前。

## 超时取消时在途请求的花费

单币会议超过 `symbol_timeout_s` 被取消时，那一刻已经发出、还没返回的模型请求以前记不到钱（返回时会议已结算）。现在叫停（`abort`）的同时，把每个在途请求按估算记一笔：输入 token ≈ 提示字数 / 2（偏高一点）× 输入价 + 本场已完成回答的平均输出 token（一次都没有按 2000）× 输出价，花费标 `estimated`：`meeting_live` 的 `cost_estimated = true`，决策日志里该条失败记录的 `output.cost_estimated = true`、摘要末尾「（花费含在途请求估算）」。后台线程里的请求最终会返回并带上 OpenRouter 的真实花费，这时把估算换成真实值，差额补进今天的花费（`late_cost` → 指挥官 `_charge`，回到事件循环里记）。没有再去查 OpenRouter 的 `/generation` 接口：请求返回时 `usage.cost` 已经是真实值，不需要多一次调用；请求一直不返回（断网）则停留在估算值。

`meeting_live` 的 `llm_calls` 每条多 `retries`：1 = 这次调用本身是上一次出问题后的自动重试，0 = 普通调用（顶层 `retries` / `retry_reasons` 仍是整场的重试次数和原因）。

最坏一轮（波数 × `symbol_timeout_s`）不小于开会间隔时只提示，不会自动拉长间隔：15m 档 5 张卡 1 波，单币超时 900 秒 = 15 分钟，`check-config` / `status` / 设置页「军师团节奏」会写明「最坏一轮要 15 分钟，赶不上下一轮」；可调小 `symbol_timeout_s` 或 `max_cards_per_round`。

### 临时会 / 卡龄检查 / 固定时间 / 超额放慢（`[schedule]`）

- **临时会**（`event_meeting_enabled`，2h 起默认开，15m–1h 关）：卡有效期里出了事件，只给那一个币补开一场，结论并进现有卡（版本 +1，有效期不延长，`refresh_reason = event:<触发>`），不重开整轮。关掉时关键位突破 / 大消息 / 新入池照旧重开整轮。触发名单 `event_triggers`（不在名单里的事件不开会）：`key_level_break`（慢环每次检查时拿特征快照的最新价 `last_price` 和卡上该币的关键位比：阻力位价格高于它、支撑位价格低于它算在外侧；`outside` 模式在外侧就算，`cross` 模式只有从里侧到外侧那一下才算，见下面 `key_level_trigger`）、`move_since_card`（离该币上次开会的价格 ≥ `move_since_card_atr`=3 倍最长持仓档 ATR）、`new_head_symbol`（新币进头部档）、`predictor_against_card`（预测员连续 `predictor_against_runs`=2 次看反，订阅 `App.against`）、`news_high_impact`（大消息）、`stale_card_on_entry`（见下）。`key_level_trigger` 定 `key_level_break` 怎么算：默认 `outside` = 价格在关键位外侧就算（价格一直在外面，隔够同币间隔就再开）；`cross` = 只认从里侧穿到外侧那一下（记 `key_level: crossed`），回到里侧重新上膛。每条结论（某场会出的指令，按 `meeting_id` + 关键位认）按开会开始时的价定每个关键位在哪一侧（开会前 5 分钟内没看到价就用出卡后第一次看到的价），那时已在外侧的位不算（记 `key_level: suppressed_already_beyond`）；整轮会里沿用 / 原样留着 / 持仓只盯的币结论没变，两侧和没开上的穿越都保留。两侧每次检查都记，不受开会间隔和失败退避影响（间隔只管开不开会）。一次穿越只换一场会：会真正开始（计入当天场数）就用掉，开不成也不重排；没开始（不在池里、卡失效等）就留着。同币间隔内的穿越排队过期后会重排（只重排自己这个原因、只在币还在池里时），等过开会间隔和同币间隔仍没开上就作废（记 `key_level: expired`），不会被每日上限 / 定点开会压到隔夜再补。两侧状态存在 `market_view.json` 的 `level_side` / `level_cross`，重启不重开。同币间隔 `event_symbol_gap_min`（含正式会，0 = 不限，但内部仍隔 5 分钟，免得关键位一直被穿时连着开；开会失败的币另隔 15 分钟才再排）、每天（曼谷日）最多 `event_max_per_day` 场（0 = 不限，场数照常计数）；持仓币优先；排队超过 30 分钟没轮到就丢（事件还在会重排）；失败也算一场（间隔内不重试），花费照常计入日上限。2h：前三项、间隔 60、50 场/天；6h：五项、60、20；12h：六项、90、20；24h：六项、120、24。
- **临时会并发**（`event_concurrency`，默认 1）：同时最多开几场临时会（不同币）。1 = 和以前一样一场一场排队（在开一场时什么都不派，整轮在开时也不开临时会）；0 = 跟 `concurrency` 一样；不能大于 `concurrency`。大于 1 时：
  - 主循环每次检查按 `pop_event` 原来的顺序（持仓币优先、同币间隔、失败退避 15 分钟、每日场数、日花费、排队过期）一场一场取，取到就同步预留（`claim_event`）：这个币、它占的当天场数、它的预估花费（最近几场平均）在派下一场之前就已算上，所以同一刻派出的几场不会同币重叠、不会一起越过 `event_max_per_day`（0 = 不限照旧），也不会一起越过日花费上限（已派未预记的场按估算算进今天花费，和一场一场开时一样最多超出一场）。预留在会议真正开始时转成正式计数，开不成就释放。

- 24h 档巡逻兵改 4% / 2%。开仓前卡龄 `entry_max_card_age_min` = max(60, 1.5 × 推荐最长持仓)：2h 开会 360 / 6h 1080 / 12h、24h 2160（上限放宽到 4320）。
- **止损口径（#138 合并后）**：提示词里的「止损倍数按 X 计」改成 `stop_atr = √(短周期 ATR × 长周期 ATR)`（没有长周期就是短周期 ATR，不乘时段系数），并给每档建议范围（`profiles.STOP_HINT`：30m 0.55–0.9、1h 0.8–1.25、2h 1.15–1.85、4h 0.85–1.35、8h 1.05–1.65、12h 1.1–1.7、24h 1.1–1.75；硬范围仍是风控员的 min/max_stop_atr）。关键位范围 = 2.5 × 倍数中值 × stop_atr（持仓期内价格 94% 的时候不会走到 2.5 个止损以外）；没有建议范围时仍用旧公式 σ×ATR×√(持仓/周期)。
- **没做（预测员线程）**：预测员 8h+ 改 15m / 1h K 线（#140 已做）。

## 作战卡 = 指令池

作战卡不再是「一轮一张、整张到期」，而是按币各自有效期的指令池：

- 每场会出一条币指令，带 `issued_at`（哪一刻开的会）、`expires_at`（该轮开会间隔 + 提前量）、`meeting_id`。
- 新一轮只替换这轮开过会的币；没开会的币原样留着，到各自的点自动消失（观望指令也一样）。
- 持仓币的指令不因到期消失，只清空信号（不再开新仓），直到被新结论替换。
- 临时会只更新那一个币，到期时间跟当前这一轮走。
- `[schedule] reuse_extend_expiry`（默认 `false` = 现状）：整轮里因为 `symbol_min_interval_min` 没重开会、沿用上一张卡的币，现状保留原到期时间——它若是上一张卡快到期前开的临时会，会在新卡出来后不久就消失（2026-10-28 03:48 的卡：XRP 03:43 的结论 04:07 就到期，8 个币 04:07–05:48 没有可交易的指令）。打开后沿用的指令顺延到新卡的到期时间，但从它自己的 `issued_at` 算最多活一个卡有效期（`issued_at + card_ttl_min`，放慢时按放慢后的有效期），永不缩短；没有 `issued_at` 的旧指令不动。这条规则作用于新卡上每一条没到期的旧指令，不只是本轮挑中的币：没被挑中的币（比如上一张卡快到期前开过临时会、这轮没进名单的）同样顺延，整轮选币期间并进卡的临时会也一样；本轮开会的币本来就是新到期时间，上一轮正常开会的指令已经是 `issued_at + 有效期`，不受影响。研究时的大盘方向（指令的 `source_market_view_id` 对应的那一版）和此刻生效的方向不同、或查不到的不顺延（最近 512 次发布的「版本 → 方向」存在 `data/market_view.json` 的 `view_dirs`，重启后照样查得到；这个键之前的旧文件、或没写研究版本的旧卡查不到。旧代码读这个文件时忽略这个键，回滚安全）——大盘已经翻转，旧结论按原到期时间消失。选的是封顶而不是「剩余太短就重开会」：重开要多花一场会，而且违背同币最小间隔；封顶保证沿用的结论不会比当场开会得到的结论活得更久，下一轮到点时它早已过了最小间隔，会正常重开。推荐 Demo：`true`。
- `commander.current()` 返回的是过滤后的视图（快环 / 风控员 / 持仓管家都读它），池空了返回 None。
- 落盘：`data/battle_card.json`（原子写）带各币时间戳，重启按原到期时间恢复；复盘流水 `card_review/cards.jsonl` 每条指令的窗口用币自己的出会 / 到期时间。
- 面板每行显示「来自 hh:mm 的会 · hh:mm 到期」，离到期不到 10 分钟变灰，过期的币不显示（持仓币标「已到期，持仓中，不再开新仓」）。
- 一轮一场都没开成：照旧记失败并退避重试，池里原来的指令不动。

## 单币方向翻转要确认（`[schedule] card_flip_confirm`）

2026-10-24 起的复盘流水（`data/card_review/cards.jsonl`，1244 场单币会、51 个币，同一个币两场会中位间隔 67 分钟）：做多 ↔ 做空直接翻了 88 次，有下一场会的 82 次里 19 次（23%）下一场就翻回去，只有 18 次（22%）下一场同向确认，45 次（55%）下一场转中性；做多 / 做空转中性 286 次，101 次（35%）下一场回到原方向。同期持仓管家按卡规则（反向卡 / 中性卡）平了 11 笔，合计 −600.1 U；按 `card_flip_confirm = 2` 回放，其中 7 笔（−342.3 U）平仓那一刻的变化还只是候选，不会触发卡规则（只说明不会在那一刻被卡规则平，之后怎么走没有反事实）。

| 键 | 取值（默认在前） | 作用 |
|---|---|---|
| `card_flip_confirm` | `1` / `2`–`6` | `1` = 新结论立即生效（现状）。`2` 起：一个币的新结论和卡上生效的方向不同（做多 ↔ 做空，或做多 / 做空转中性）时先不换，记成「待确认翻转」；同一个币连续这么多场会（整轮、临时会都算，第一场算 1）都和生效方向不同就换成最新那场的结论——反向和中性交替也算（下一场转中性的占翻转的 55%，要求同一方向连续会让一个过时方向一直留着）；中途有一场回到原方向就取消候选、照常换上新结论 |
| `card_flip_confirm_min` | `0` / 分钟 | 候选从第一次出现起至少过这么多分钟才确认，和场数同时满足；`0` = 只看场数 |

- 方向的口径和持仓管家一致：`bias` 是 long / short 就是它；闸门改成 `no_trade` 的（`no_trade_from`）按会议原方向；到手即作废（`stale_on_arrival`）、`both`、会议本身观望的 `no_trade` 算中性。从中性转出一个方向不算翻转，立即生效。卡上没有这个币（没开过会、或指令已到期被拿掉）也立即生效。
- 候选期卡上留着原来那条指令（方向、`issued_at`、`meeting_id`、关键位都不动），只清空信号、有效期跟新结论走，理由前面写「待确认翻转（1/2）：…｜原结论：…」。于是：不开新仓立刻生效（两个方向都不开）；持仓管家的反向卡 / 中性卡规则看的是这条确认过的方向，确认前不因翻转平仓、也不收紧；决策模型复查、止损、回吐保护、最长持仓照常。
- 转中性也要确认：不开新仓本来就立刻生效，只是卡规则要等确认。`[keeper] card_neutral_action = "hold"`（现在的设置）时中性卡本来不平仓，这条只在改成 `tighten` / `close` 时多拦一层。
- 记录：每次进入候选、确认、取消、作废都写一条军师团 info 决策记录（`output.card_flip` = `pending` / `confirmed` / `cancelled` / `dropped`，带原方向、最新一场的方向、第几场、需要几场、候选持续了几分钟）；出卡记录的 `pool.<币>.flip_pending` 写候选状态，面板作战卡那一行加「待确认翻转」标记并写明「待确认翻转 k/N（还没到 `card_flip_confirm_min` 时加「，等满 X 分钟」）：会议改判 X，卡上仍按 Y 只看不做」；场数显示不超过 N（场数够了在等时长时显示 N/N）。会议本身的结论照常记在单币开会记录和复盘流水（`cards.jsonl` 记的是会议结论，不是候选期留在卡上的那条），方向记分不受影响；面板「历史卡」读的也是这份流水，显示会议原结论，不显示候选期卡上实际生效的那条。
- 候选跟着卡上留着的那条指令走：没有持仓的币，那条指令过了有效期就从卡上拿掉，候选随之失效——下一场会按「卡上没有这个币」立即生效，并记一条 `dropped`；持仓币的指令不因到期消失，候选一直留到确认或取消。临时会也一样：卡上已过期、没有持仓的指令不算生效方向（和整轮一致），不会被当成原方向留回卡上。
- 大盘台翻转后：N ≥ 2 时各币的新方向同样要等确认，持仓管家的反向卡 / 中性卡规则因此比现在晚一场会（中位约 1 小时）才对大盘翻转后的新方向起作用。
- 落盘：`data/card_flip.json`（原子写），重启后读回；每条候选记着留在卡上那条指令的身份（`meeting_id|issued_at`，不含方向：重启时按新的类别上限夹卡可能把它改成 no_trade），卡上那条对不上（被换掉、旧代码开过会）就作废、记 `dropped`，从下一场会重新数。改回 `1` 时下一场会就清掉所有候选，留在卡上的那些候选期指令等各自的下一场会照常换掉。
- 这几项在面板「军师团 → 每个币的会」里改，也能写进 `slow.pending.toml`；改了要重启 `jiaoyi run`（作战卡调度在启动时读配置）。

推荐的 Demo 配置（`config/slow.pending.toml`）：

```toml
[schedule]
card_flip_confirm = 2
card_flip_confirm_min = 0
```

回退到这个功能之前的版本：先把 `[schedule] card_flip_confirm`、`card_flip_confirm_min` 从 `config/slow.toml`（和 `slow.pending.toml`）删掉（旧代码的配置禁止多余字段，留着会拒绝启动）；`data/card_flip.json` 旧代码不读，可以留着；作战卡存档里没有新字段，旧代码照样读回。候选期留在卡上的指令就是一条只看不做的普通指令，旧代码下一场会照常换掉。

## 面板「重新开会」

`refresh_cards` 指令 = 整条链真跑一遍：选币（同一套筛选，写 `symbol_pool.json`）→ 总盘会 → 每个币完整分析会 → 新卡。
`reason=manual` 不沿用上一张卡、不受同币最小间隔限制，但仍受 AI 日费用上限。回执等跑完才写：
「已重新开会：选了 N 币 / 上会 M 币 / 用时 / 花费」。总盘会有自己的模块状态（`market`：上次 / 下次 / 摘要「挑了 N 个 / 落选 M 个」），
军师团的 `last_run_at` / `next_run_at` 也已填上。

## 选币节奏

选币跟开会间隔档位走（15m 档 15 分钟选一次，24h 档一天一次），不再固定每小时。`app.toml` 的 `screener_interval_min`
默认等于档位的开会间隔（下限 15 分钟，保护币安接口权重），自己写了就用自己的；切档位时一键全换会一起清掉。
每一整轮会议前都会先选币（2 分钟内刚选过就不重复），顺序 选币 → 总盘会 → 军师团。选币的 `next_run_at` 按这个间隔更新。

## 币安限流（418 / 429）

分析师拉 K 线、资金费率、持仓量都走 `slow/binance_gate.py`：全局共用一个最小请求间隔；收到 418 / 429 就读 `Retry-After`
记下解封时间，封禁期内所有请求直接抛 `RateLimited`，不再打给币安（多发只会延长封禁）。封禁状态和已用权重读数放在 `market/rest.py`，快环回填 K 线、离线工具、分析师三边共用：任何一边被封，另外两边立刻停手。

开会时只要有币因此没开成，军师团整轮暂停：不算会议失败、不退避，模块状态显示「币安限流，X 分钟后重开」；
解封（+5 秒）后用原来的开会原因自动重开这一轮，不等下一个间隔。

## 美股 / 金属永续（TRADIFI_PERPETUAL）

币安把美股、金属永续的 `contractType` 标成 `TRADIFI_PERPETUAL`。选币（`binance_stats`）和执行层的下单精度（`lot_filters`）都放行它，
常量在 `contracts/common.py::PERPETUAL_CONTRACT_TYPES`。分类先看名单（含 PAXG / XAUT 归金属），名单外的按 exchangeInfo 的
`contractType / underlyingType / underlyingSubType` 自动识别：商品 / 金属 → 金属，其余传统资产 → 美股科技。

**进池开关**：`slow.toml [screener] allow_tradfi`，默认关（等在 Demo 上把开平仓、保命止损、行情流整条链验证完再开）；关着时 TRADIFI 合约在池里显示「传统资产永续暂未开放」。打开后也只放行美股和贵金属 / 商品；港股、韩股、A 股、盘前、外汇和认不出类型的传统资产一律不进池，选币记录里写「暂不支持的传统资产类型（…）」，等各自的交易时段做好再放。

美股 / 加密股合约只在美股常规盘的开仓时段开新仓：**开盘后 15 分钟到收盘前 15 分钟**（美东时间，自动跟夏令时，周末和 NYSE 休市日不开）。
时段判断在 `core/us_hours.py`（风控员和慢环共用）。可配置：`app.toml [fast_loop]` 的 `us_hours_gate`（默认开）、`us_open_delay_min`、`us_close_lead_min`。时段外：休市时照常进池参与选币，
卡上该币标「休市不可做」（信号清空），风控员也拦开仓；已有持仓不强平，止损和持仓管家照常。金属不受限。

## 主流币 = 市值前 N

选币的「主流币」类别不再是写死的 7 个，而是**市值前 `major_top_n` 名（默认 20）**：`slow/majors.py` 每天从 CoinGecko 免费接口（无需 key）拉一次市值排名，
去掉稳定币和包装 / 质押币（WBTC、stETH 等），选币时再去掉币安没有 USDT 永续的，往下补满 N 个，对应到币安永续（`1000PEPE` 这类前缀按基础币名对）。结果缓存在 `data/majors.json`，
拉取失败沿用缓存（不管多旧），没有缓存就回退写死的 7 个（BTC ETH BNB SOL XRP DOGE ADA）；`major_top_n = 0` 也是只用这 7 个。

`slow.toml [screener]`：`major_top_n`、`major_include`（手动加入，如 `["LINK"]`）、`major_exclude`（手动排除，按山寨币算）。
选币记录里每个主流币的理由写「主流币 · 市值第 N 名」（手动加入 / 回退名单也各有说明）。

## 军师团 / 总盘会的提示词（按最长持仓档）

提示词不再是股票那套，改成币安永续写法，跟 app.toml 的 `hold`（最长持仓档）走，重启生效，不加新开关。

- **一张 7 档词表**：数字在 `core/profiles.py`（持仓时长、指标周期、手续费占比、必须有进场区间），文字在
  `slow/ta_prompts.py`（short ≤2h / mid 4h / long ≥8h 三组）。公共说明、总盘会挑币、大盘简报、转卡都只从这里取词。
- **公共说明**（所有 TradingAgents 角色共用）只跟档位有关；**每场会不同的东西**（总盘会的判断、挑这个币的
  理由、tickSize、持仓说明）走 `PerpGraph` 的 state（`slow/ta_nodes.py`），不进配置，同时开几场也不会串。
  固定币 / 持仓强制开会的币不是总盘会挑的，写成「这轮不是挑的，每轮都开会」，不提持仓。
- **替换的角色**：多空研究员、风控三人、新闻分析师（加密币；美股永续照旧走原版）。状态读写和原版一致。
- **评级兜底**（代码，`rating_guard`）：卡不能比研究经理和组合经理里较弱的那个更强。任一 Hold 或方向相反 →
  观望；偏向（Overweight / Underweight）→ 仓位档最多 M（`lean_size_tier`）；两人都明确 Buy 或都 Sell 才到 L。
- **TradingAgents 原版记忆停用**（`memory_log_path=""`，股票口径；`memory.md` 不删）。
- `data/prompts_active.json`：启动时写入当前生效的提示词原文，给面板显示。
- 已知限制：自定义持仓时长按不短于它的那档写，`{HM}` 写实际分钟数，`{H}` / `{FEE}` 写那一档的。

### 行情分析师和简报的数据（币安，按档位）

- **指标 / 价格快照周期**跟档位（30m、1h 档 5m；2h 档 15m；4h 档 1h；8h 以上 4h），根数 = 回看天数 ×（1440 / 周期分钟），取 500 根。
  TradingAgents 原来的「验证快照」读雅虎日线（STRK 0.049 变 0.05、1000PEPE 没有数据），换成币安永续已收盘的 K 线，价格按 tickSize 的小数位写。
- **分析师 K 线**见 `core/profiles.py` 的 `ANALYST_KLINES`（短档含 5m）。
- **大盘简报**（`slow/brief.py`）按这一档的字段取数：short = 1h / 4h / 24h 涨跌、24h 区间位置、成交倍数，背景 20 日线和 7 天涨跌；
  mid = 4h / 24h / 3 天涨跌、3 天区间位置、1h RSI；long = 24h / 3 天 / 7 天涨跌、20 日线、4h 与日线 RSI。每部分各自失败写「暂不可用」。
- **情绪分析师（加密币）**看币安持仓人群：全市场账户多空比、大户持仓多空比、主动买卖量比、持仓量，加这个币近 24 小时的标题
  （`slow/crowd.py`）。四项全部拿不到、也没有标题时，报告写「数据不可用」并按缺报告降一档仓位。美股永续仍走原版。Reddit 这版不接。

### 进场区间（`entry_zone`）

## 总盘输入口径与旁路诊断

总盘候选表与池面统计明确区分 `up / down / flat / missing`，零涨跌只计持平；缺失与非有限数显示 `n/a`。本次属于获授权的模型输入纠错，会改变总盘 prompt 的数字说明与时间口径文本，不能称模型 payload 完全未变；持仓管家的 payload、交易门槛、确认规则、BTC 条件、周期、预算和排队规则均不因此改变。

表内 `completed_hour` 是最后完整 UTC 小时 K 线开收盘变化；`completed_4h_close_span` 是最后完整小时收盘价相对四根之前完整小时收盘价的变化；`current_hour_open_to_ticker` 用当前小时开盘和 ticker 价；`ticker_24h` 属于交易所滚动 ticker 窗口。哨兵另用精确已收盘 1m 线的滚动 60 分钟窗口，不能当作同一“1h”。简报各期限仍用原公式与原数据，可能含未收盘末根；它的窗口、缓存和生成时钟分别标记，不偷偷统一成另一个收益公式。

`SymbolPool.source_metadata` 是默认空的兼容旁路字段，不塞进原数值 `metrics`，不参加打分。每次 stats 返回携带本次独立来源/请求/响应与实际 K 线边界；旧池、旧缓存或解析失败保持空/未知。ticker 的 `closeTime` 只标统计窗口结束，不能冒充最后成交时间；请求/响应/池组装时刻也不能冒充真实价格事件时间。简报文本与来源快照在同一锁下取得；缓存命中、部分失败、全部失败保留旧内容均保留原生成时钟，未知价格时钟不补造。

总盘本地诊断在 `data/market_diagnostics/`，逐次调用以局部 `trace_id` 连接 request accepted、每次真实 invoke/retry 的完整文本、结构化业务响应、失败、实际发布/旧结果丢弃；scheduled 的逐币表只含真实 free 候选，breadth 仍为原池，market-only 表为原池全体。单币研究、管家、SDK/HTTP 对象与 headers 不进入这份诊断。原 `market_meeting` 保留既有 `ts` 语义，新增发布时刻、MarketView、trace_id 与 pool 请求时刻便于关联；旧记录不回填成已知来源。未观察到模型调用不能推断“已发送”或“没有调用”。

每次实际执行的 flip 检查另写 `data/regime_checks/`，包含 quiet、保存阈值与方向条件、确认前后计数、参考/样本窗口及阻拦原因；原 UI 事件日志与疑似节流保持原行为。关闭/互斥等未执行检查不是 quiet，也不能拿发事件数冒充全部调度次数。条件诊断只解释保存输入，不再次调用 `step` 或改确认状态。

旁路的 `write_started_at` 只表示后台写入开始，不代表落盘完成或精确可见时间；没有 fsync/receipt 就不补造完成证据。旁路使用有界后台队列，不等待磁盘；每目录每日最多两段、每段 32MiB，文本上限 262144 字符，单条上限 512KiB，队列满或写入失败可丢诊断并告警，不能据日志缺口断言没有检查。URL 查询与常见凭证模式脱敏，文本记录明确原文/存储哈希、脱敏、截断和是否可逐字复演；超限标记不冒称完整。故障、慢磁盘、脱敏或时钟不可用不得改变模型调用、重问、判断或费用路径。诊断只落本地，不上传真实 prompt、行情或回放数据。

## 单币会议偏空整改开关（`[meeting]`，`slow/bias_fix.py`）

## 大盘判断的时间和口径（`[meeting]` + `[market_desk] republish_after_min`）

依据 2026-10-28 审计：大盘台方向没变就不发新版，01:47–04:09 的各币会议拿到的都是 23:32 发布的那段话，而且没有时间（只有 `publish_intra` 开着时才标发布时刻）；大盘判断和「4 小时之内」里的主动买卖占比是全池的，分析师当成了本币的。四个键都不写 = 现状，提示词一字不差；都中立（只写时间、年龄和口径，不带方向）。`[meeting]` 三项改了要重启，可以在面板设置页「军师团」或 `config/slow.pending.toml` 的 `[meeting]` 改；`republish_after_min` 经 `config/slow.pending.toml` 的 `[market_desk]` 改。

| 键 | 取值（默认在前） | 作用 |
|---|---|---|
| `[meeting] regime_time_label` | `false` / `true` | 各币会议的大盘判断前写「（大盘判断 HH:MM UTC 发布，距此刻 N 分钟）」（`publish_intra` 开着、观点是大盘台的时候写「大盘台 HH:MM UTC 发布的 4 小时判断，距此刻 N 分钟」），`meeting_setup` 记 `regime_age_min`；持仓管家复查快照和拍板人进场快照的 `current_market` 加 `age_min` |
| `[meeting] regime_max_age_min` | `0` / 分钟 | 大盘判断发布超过这么多分钟：会议里那段前缀加「已过期，仅作参考」（不开 `regime_time_label` 也加，带时间），`meeting_setup` 记 `regime_stale`；快照的 `current_market` 加 `age_min` 和 `stale = "已过期，仅作参考"`。0 = 不标 |
| `[meeting] pool_scope_label` | `false` / `true` | 大盘判断前缀加「其中的涨跌、主动买卖占比等数字是全池口径，不是这个币自己的」，「4 小时之内」那段前面加「全池口径：」 |
| `[market_desk] republish_after_min` | `0` / 分钟 | 大盘台接管时，方向没变、当前生效的大盘台观点发布超过这么多分钟，就按同一方向把这一轮的话、概率和数字重发一版（版本号 +1，`market_desk_state.json` 的 `latest.republished_same_direction = true`）。方向和翻转参照不变；**不唤醒持仓复核**（只有方向真的变了才排队复核），也不重置 `publish_min_gap_min` 的计时（从上一次方向发布算，重发时刻另记 `last_republish_at`），所以不会推迟真正的翻转。大盘台日志那一行带 `republished_same_direction = true`，方向记分（`market_score`）不把它算作一次发布。0 = 方向没变不发 |

大盘台接管（`mode = "replace"`）时，`regime_max_age_min` > 0 要求 `republish_after_min` 大于 0 且小于它，否则方向不变时每份大盘判断都会过期；启动、面板保存和待生效配置都按这条拦（报错写明两个值）。Flash 管大盘时每轮都发布，不查这一条。管家和拍板人的 Jev 记录（`input.jev.market_age`）写快照里的 `age_min` 和是否 `stale`，没开就没有这个键，方便按它分组分析。

推荐的 Demo 配置：`regime_time_label = true`、`regime_max_age_min = 120`、`pool_scope_label = true`、`republish_after_min = 60`（大盘台 15 分钟一轮时，各币会议看到的大盘话最旧约 75 分钟）。

回退到这个功能之前的版本：先把这四个键和 `[schedule] reuse_extend_expiry` 从 `config/slow.toml`（和 `slow.pending.toml`）删掉（旧代码的配置禁止多余字段，留着会拒绝启动）。

## 会议输入的新鲜度（`[meeting]`，不能有延后信息）

依据 `stale-input-audit-2026-10-28`：「上一根已收盘小时线」被当成「近 1 小时」，单币会议没有实时价，临时会用旧简报。下面九个键都不写 = 现状，提示词和配置一字不差；`[meeting]` 和偏空整改那几个键一样只在 `slow.toml` 里改，面板设置页不放，**改了要重启主程序**（`[meeting]` 不在热生效名单里，引擎和指挥官启动时读一次）。

| 键 | 取值（默认在前） | 作用 |
|---|---|---|
| `snapshot_interval` | 不写 / `"5m"` `"15m"` `"30m"` `"1h"` `"4h"` | 行情分析师的已收盘快照（`get_verified_market_snapshot`）和 `get_indicators` 用的 K 线周期；不写 = 档位的（4h 档 1h，最旧约 1 小时加开会时长）。提示词里的 `{IND}` 和多空比的统计周期跟着换 |
| `snapshot_label` | `"legacy"` / `"neutral"` | neutral：快照不再叫 source of truth，写「最后一根已收盘 K 线 HH:MM 收盘，距现在 N 分钟，之后的价格变动不在快照里」；行情分析师的说明同样改写 |
| `live_price_line` | `false` / `true` | 会议说明加一行：开会时币安最新成交价、最后一根已收盘 K 线（快照周期）几点收、距现在几分钟、现价离它涨跌多少，没走完的那根标成 partial 并给开 / 高 / 低；转作战指令前再取一次现价写进转卡提示词（距开会开始变了多少，已越过失效价或区间整段在价格后面就选 no_trade）。每场会 4 个公开请求 |
| `stale_on_arrival` | `false` / `true` | 转卡之后代码再核对一次（不靠模型）：做多现价 ≤ 组合经理 `Invalidation` 行的价、做空现价 ≥ 失效价；或者开会开始时价格还没越过进场区间（在区间里或正确一侧），转卡时已整段穿过去（做多跌穿、做空涨穿）。开会时就在区间另一侧（等价格回来的挂法）或拿不到开会时的价，不按区间作废。命中按 `stale_on_arrival_action` 处理，理由写 `stale_on_arrival：…`，记日志、开会实况和 `meeting_setup.stale_on_arrival`。现价取转卡前的币安成交价，取不到时用关键位那一步的最新 K 线价；用的哪个记在 `meeting_setup.stale_guard_price_source`（`live_ticker` / `levels_fallback` / `unavailable`）。开了它，开会开始时也取一次价（即使 `live_price_line` 关着，只是不写进说明） |
| `stale_on_arrival_action` | `"watch"` / `"no_trade"` | watch：只盯不开，方向不动，清掉信号和进场区间（和指挥官 `_watch_only` 一样），持仓的反向信号、方向记分照旧，管家的反向卡规则也不会因为它平仓；no_trade：改成观望 |
| `input_time_labels` | `"legacy"` / `"explicit"` | 总盘会表格 `takerBuy1h` / `OI1h` 改成 `takerBuy_closedHour[09:00-10:00Z]` / `OI_closedHour[…]`（窗口来自选币来源元数据，不知道写 `time unknown`）；单币会议资金费率写「Last settled funding rate (settled at HH:MM UTC)」，再加 `premiumIndex` 的实时估算和下次结算时间，持仓量写明首尾两个整点 |
| `market_table_rolling` | `false` / `true` | 整轮总盘会的池子概况多一行 `rolling_60m`：每个币 1 分钟 K 线，从「开会时刻取整到分钟 − 60 分钟」那一分钟的开盘价到此刻最新价（最后一分钟没走完），10:54 开会就是 09:54–10:54。起点那一分钟没有的币记缺失；整行取不到（含限流）写 `rolling_60m unavailable (…)`，总盘会照开。开会实况（面板「开会过程」）的输入在会前先显示，会后另加一步「模型实际收到的表」，开了这一项或 `input_time_labels = "explicit"` 时才有。原来的 `completed_hour` 一行不变。只改整轮总盘会，不改 Flash 只更新大盘（那一处归大盘台） |
| `lessons_scoring` | `"raw"` / `"excess"` | 教训（下一节）怎么给卡打分。raw：会后一个持仓期的原始涨跌，山寨币另比同期 BTC。excess：和 `slow/card_score.py` 同口径，发布时刻起 4 小时、方向 ×（币 − 同期币池等权收益），读 `data/card_score/scored.jsonl` 已算好的结果、不另拉 K 线，不扣手续费，观望卡看相对币池走了多远；提示词多空写法对称。需要面板进程在跑方向记分（`card_score_every_min` ≠ 0），否则攒不到 30 张就不写。只影响之后的汇总，已写的教训不变。这一节下面列的开关（偏空整改、输入新鲜度、`lessons_scoring`）现在也能在面板设置页「军师团」里改，或写进 `config/slow.pending.toml`；改了要重启（模型 / 通道 / `analyst_klines` 仍只能改文件）|
| `latest_market_regime` | `false` / `true` | 整轮里每个单币会拿到并发名额、真正开始时取当时最新发布的大盘判断（本轮中途 Flash 更新过就用新的），卡上该币的 `source_market_view_id` 跟着用那一版；`meeting_setup` 记 `regime_source`（round / latest）、`regime_market_view_id`、`regime_observed_at` |
| `event_brief_refresh` | `false` / `true` | 临时会开会前刷新大盘简报（简报服务自己 10 分钟内不重复拉）；刷新失败记一条错误、用上一份 |

推荐的 Demo 配置：八个开关全开、`stale_on_arrival_action` 用默认的 watch，`snapshot_interval = "15m"`、`snapshot_label = "neutral"`、`input_time_labels = "explicit"`。新增请求都走 `binance_gate` 限流闸：每场单币会约 5 个、每轮总盘会约池子大小个。
