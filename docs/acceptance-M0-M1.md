# M0 / M1 纸面验收清单（24 小时）

给 Aaron 在 Mac mini 上照着跑。全程**模拟盘**（`mode = "paper"`），不动真钱。每一项后面写了「怎么看」和「不通过怎么办」。

> 约定：✅ = 你亲眼看到就算过；🤖 = 运行 `python -m jiaoyi.acceptance` 由脚本替你核对（第 4 节）。
> 带「待定」的命令是对应工程师还没交付的，等 README 写明后以 README 为准。

## 3. 红线（任何一条出现，验收直接判不通过）

1. 有任何一笔开仓没有对应的风控员放行记录。
2. Jev 超时 / 报错的那个信号后面出现了开仓。
3. 任何一笔开仓 30 秒内没有保命止损。
4. 放行的单杠杆、名义价值、风险金额超过 `config/risk.toml`。
5. 当日亏损达到熔断线后又开了新仓。
6. 配置超范围 / 缺项时程序居然启动了。
7. 币安账户里有仓位，但系统「不知道」（对账员没发现）。

1–5 脚本会检查；6 靠 0.3；7 靠第 6 节的演练。

## 4. 24 小时跑法

1. 启动全部服务（hummingbot-api、Condor、大脑程序），记下开始时间。
2. 让它自己跑满 24 小时，期间你只做三件事：每隔几小时看一眼面板；收到 Telegram 告警就记一下；不要手动改配置。
3. 满 24 小时后运行：

   ```bash
   python -m jiaoyi.acceptance --stage m1 --hours 24
   ```

   `--stage m0` 只验执行底座（没接 Jev 时用）。输出里 `✓` 通过、`✗` 失败、`·` 只是信息；有任何 `✗`，退出码为 1。检查项：

   | 项 | 含义 |
   |---|---|
   | 运行时长 | 日志覆盖 ≥ 24 小时 |
   | 心跳 | 每个角色 3 分钟内报过状态，且不是 down |
   | 每笔开仓都有风控员放行在先 | 红线 1 |
   | Jev 失败的信号没有开仓 | 红线 2 |
   | 每笔开仓 30 秒内挂上保命止损 | 红线 3 |
   | 放行指令符合硬上限 | 红线 4 |
   | 同时持仓不超上限 | `max_open_positions` |
   | 对账员没有遗留问题 | 没有「发现了但没修好」的记录 |
   | Jev 延迟 | p95 ≤ 1.5 秒 |

4. 把输出整段复制给协调者（里面没有密钥）。

## 5. 怎么读回放汇总

```
触发 280，问决策模型 280 次（失败 0，回答“做”141）
风控员放行 32，拒绝 248
成交 32，已平 32，未成交 0
胜率 12%（4 胜 28 负）  净盈亏 -98.81 U（每 1 万 U）
拒单原因：拍板人不认可 139 / 止盈太小，覆盖不了手续费 109
```

- **回放里的 Jev 是 mock（随机 50% 答“做”），不看行情。** 所以胜率、盈亏只能说明「门槛 + 手续费 + 延迟」的影响，**不能**当作 Jev 判断力的证据。要评估 Jev，用真实录制的答复（`--jev recorded:文件.jsonl`）。
- 手续费默认取 `config/risk.toml` 的 `taker_fee_bps`（单边 5bp，来回 10bp），可以用 `--fee-bps 4` 到 `10` 试敏感性。
- 延迟：`--jev-latency-ms`（Jev）和 `--order-latency-ms`（曼谷→币安）。上次一日回放的参考：154 触发、10 笔、胜率 30%、−27U/1 万，拒单多为「止盈太小不够手续费」。
- 回放里持仓结束没平的会按最后价格强平，退出原因记为 `replay_end`。

## 6. 故障演练（M1 通过后做，每项约 5 分钟，都在模拟盘）

| 演练 | 怎么做 | 应该看到 |
|---|---|---|
| Jev 挂了 | 把 `JEV_API_KEY` 临时改错，或断网 | 之后的信号全部被拒，原因「决策模型不可用」；**没有新开仓**；已有持仓保持，不会乱平；恢复后自动继续 |
| 没有作战卡 | 让卡过期 / 删掉 | 不出新信号；已有持仓照常盯 |
| 保命止损丢了 | 在测试网网页手动撤掉某笔持仓的保命止损 | 一分钟内对账员补挂并发 Telegram 告警，日志有 `reconciler` 记录 |
| 执行器挂了 | `docker stop` hummingbot-api | 对账员告警；恢复后核对一次、不重复开仓 |
| 系统重启 | 杀掉大脑程序再启动 | 启动后先对账一次，认领原有持仓；不会把旧持仓当成孤儿平掉或重复下单 |
| 日亏熔断 | 把 `daily_loss_halt_pct` 临时调到 `0.5` 并在模拟盘亏到线 | 之后拒绝开新仓、允许平仓；**曼谷 0 点**后恢复（“今日盈亏”清零）|
| 密钥不外泄 | `grep -r "密钥开头的 8 个字符" data logs`（把引号里换成你某个密钥的前 8 位） | 日志和决策记录里没有完整密钥 |

## 附：给开发者的日志约定

验收脚本只认这几类记录（字段见 `src/jiaoyi/acceptance.py` 文件头）：风控员放行（`risk_guard/pass`，`output` 是 `OrderIntent`）、拍板人失败（`gate/error`）、开仓成交（`executor/action`）、平仓（`executor/close`，`output.net`）、保命止损（`lifeboat/action`，带 `position_id`）、对账员未修复问题（`reconciler/error`）。角色线程写日志时请照此约定，否则验收会误报缺项。
